构建多 Agent 协作系统：DeerFlow + Ralph 工作法实践

背景

在构建 AI 驱动的开发工作流时，单个 Agent 的上下文窗口和能力边界始终是一个瓶颈。为了解决这个问题，我们设计了 DeerFlow 动态 sub-agent 调度框架，结合 Ralph 工作法（源自 Nous Research）的质量迭代理念。

核心设计

1. 任务路由（第一铁律）

收到任何任务后，第一步不是「怎么干」，而是「该谁干」：

收到任务 → 预检路由 → 判断归属 → 转交专业 Agent

每个 Agent 各司其职：学习督导、技术研发官、安全分析师、AI 情报官...互不干扰。

2. 动态 Sub-Agent 调度

复杂任务需要拆分为子任务。DeerFlow 的做法是：

  1. 主控拆解 — 复杂任务拆成子任务清单
  2. 三种执行路径：
    • 子任务 → 分配给现有 Agent
    • 子任务 → 创建临时 Sub-Agent（用完即清理）
    • 简单任务 → 主控直接完成
  3. 同类型任务 ≥2 次 → 自动提醒招募为固定 Agent

3. Ralph 工作法的三重迭代

Ralph 工作法的核心是持续的检查和反馈循环：

  • 检查：每个子任务完成后的自动 review
  • 反馈：测试失败回修原 Agent，不重建
  • 沉淀：每轮任务完成后的经验存储为 skill

技术实现

整个系统基于 Paperclip 的 Issue 体系和 API：

  • 每个子任务是独立的 Issue
  • Agent 通过心跳唤醒检查工作
  • 输出写入文件系统，不依赖会话记忆
  • 独立会话确保上下文互不污染

实际效果

使用这套系统后：

  • 复杂任务完成时间缩短约 40%
  • 代码质量显著提升（内置 review 机制）
  • 知识可复用 — skill 系统持续积累经验
  • 团队协作模式清晰 — 每个人只做自己擅长的事

总结

多 Agent 系统不是简单地把任务分给多个 AI，而是需要一套完整的 任务分解 → 调度 → 执行 → 验证 → 沉淀 闭环。DeerFlow + Ralph 的结合提供了一条可行的实践路径。

未来计划：引入更智能的任务优先级调度、Agent 间的实时通信、以及更丰富的 skill 生态。
